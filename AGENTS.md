# Project Rules & Architectural Guidelines (AGENTS.md)

## 1. Обзор проекта
Локальное десктопное приложение на Python для мониторинга рынка криптовалют (котировки + новости из бесплатных RSS-лент и открытых API).
Приложение работает **полностью автономно** без выделенных серверов и СУБД, а на финальном этапе упаковывается в единый исполняемый файл `.exe` (через PyInstaller).

---

## 2. Технологический стек и обязательные библиотеки
- **GUI (Графический интерфейс):** Использовать исключительно `CustomTkinter` (`customtkinter`). Элементы управления: чекбоксы фильтрации монет (`BTC`, `ETH`, `SOL` и др.), выпадающий список выбора периода (`CTkOptionMenu` / `CTkComboBox`), кнопка «Сгенерировать рапорт», текстовое окно превью (`CTkTextbox`) и кнопка «Экспорт в PDF».
- **Структурирование и обработка данных:** Использовать `pandas` (`DataFrame`) для агрегации, фильтрации по периодам/тикерам, дедупликации и подготовки табличных/текстовых сводок.
- **Генерация PDF-отчетов:** Использовать `FPDF` (`fpdf` / `fpdf2`) или `ReportLab` с корректной поддержкой кириллических шрифтов (UTF-8 / TTF) для формирования читаемых отчетов.
- **Сетевые запросы и парсинг:** Использовать `feedparser` для RSS-лент и `requests` (с обязательными таймаутами `timeout=(5, 10)` и заголовком `User-Agent`) для открытых крипто-API (например, CoinGecko / Binance / CoinCap).

---

## 3. Архитектура хранения данных (Легковесный кэш)
- Никаких внешних или встраиваемых БД (PostgreSQL, SQLite, Redis запрещены).
- Использовать легковесный временный JSON-кэш (например, `cache.json` / `temp_cache.json`), который **полностью перезаписывается** при каждом новом запросе («Сгенерировать рапорт»).

---

## 4. Обработка ошибок и логирование (КРИТИЧЕСКОЕ ПРАВИЛО)
- **Обязательный вывод ошибок парсинга в консоль:** Любые исключения при загрузке RSS-лент, вызовах API, разборе JSON/XML или очистке данных **не должны глушиться молча (`pass`)**.
- Каждая ошибка парсинга должна выводиться в стандартный поток вывода/ошибок консоли с указанием источника (URL/API), типа ошибки и описания (например, `[PARSER ERROR] <source>: <error_message>`), при этом приложение не должно аварийно завершаться, если один из источников недоступен (graceful degradation).

---

## 5. Совместимость со сборкой в `.exe` (PyInstaller)
- Все пути к ресурсам (шрифты для PDF, иконки) должны разрешаться через хелпер с поддержкой `sys._MEIPASS`.
- Временные файлы кэша и экспортируемые PDF должны сохраняться в рабочей директории пользователя, а не внутри временной распаковки `sys._MEIPASS`.

---

## 6. Автоматическая фиксация изменений в Git / GitHub
- Все вносимые в проект изменения должны автоматически фиксироваться локальным коммитом (`git add` + `git commit`) и отправляться в удаленный репозиторий `komile1/Crypto_news` (ветка `main`).
